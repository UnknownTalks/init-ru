# Токены — как текст становится входом модели

[К маршруту встречи](../README.md)

## Суть

Токен — единица последовательности, с которой работает модель. Токенизатор переводит текст в последовательность целочисленных ID из своего словаря. Один токен не обязательно равен слову или символу: границы зависят от конкретного токенизатора.

ID затем используется для получения числового вектора — embedding. ID, вектор и видимый фрагмент текста относятся к разным этапам представления.

## Посмотреть своими глазами

**[Открыть демонстрацию токенизации](../demos/tokens.html)** — локальная страница для браузера. В Obsidian используйте открытие ссылки во внешнем приложении или откройте файл `demos/tokens.html` из папки встречи. На сайте демонстрация открывается как отдельная страница.

Демонстрация использует токенизатор **Qwen/Qwen2.5-0.5B**, а не условное разбиение по пробелам. Он выбран как открытый воспроизводимый пример; результаты не следует переносить на все модели.

Выберите примеры на русском, английском и с кодом или введите собственный текст. Для каждого видны исходный текст, токены, ID и количество. Библиотека и словарь находятся рядом со страницей: и примеры, и произвольный ввод работают без сети. Веса языковой модели не нужны.

## План демонстрации

1. Сначала предложить участникам угадать число токенов короткой фразы.
2. Открыть русский пример и показать, где границы расходятся с границами слов.
3. Сравнить близкие строки с разным пробелом или регистром. Не ожидать заранее обязательного изменения количества: наблюдаем результат.
4. Показать код: отступы, переносы и знаки также входят в представление.
5. Сопоставить **видимые фрагменты → ID → векторы**. На странице показаны первые два, без векторов модели.

## Почему так устроено

Словарь из всех возможных слов был бы неудобен для новых слов, имён, разных языков и кода. Посимвольное представление даёт длинные последовательности. Подсловные и байтовые подходы предлагают другие компромиссы.

Например, BPE строит словарь с помощью последовательного объединения часто встречающихся пар. При использовании применяются уже подготовленные правила. Не каждый современный токенизатор — BPE; существуют и другие алгоритмы.

Некоторые байтовые токены представляют только часть UTF-8-последовательности символа. Если декодировать такой токен отдельно, можно увидеть знак замены `�`; это не означает повреждения исходного текста. Вся последовательность декодируется совместно.

## Практический смысл

- Размер контекста ограничивает последовательность токенов, доступную модели при обработке.
- Важны не только сообщения человека: инструкции приложения, описания инструментов и их результаты тоже могут попадать в контекст.
- Выход модели также состоит из токенов. Ограничения входа, выхода и общего окна нужно смотреть для конкретной модели и сервиса.
- Перевод текста в другой язык не гарантирует одинакового числа токенов.

Из фиксированного числа слов нельзя точно получить число токенов без выбранного токенизатора. Токен не является атомом смысла, а его ID не показывает важность или «разумность» фрагмента.
